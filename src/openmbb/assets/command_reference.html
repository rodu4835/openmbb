Gen2 MBB · Serial Console · Command Reference

OpenMBB

Every command the MBB serial console understands, grouped by what it does and colour-coded by how much it can hurt — from harmless reads to firmware-catastrophic writes.

Console 38400 baud · 8-N-1 Verified 2017 FXS · MBB rev 41 85 commands documented

OpenMBB no longer hard-blocks anything. Every command below — including the destructive ones that used to sit on a permanent blocklist — is now sendable. Nothing is silently refused by the transport.

Instead, the dangerous commands are gated behind understanding: before one goes out, OpenMBB shows you exactly what it does, what could happen, whether it is reversible, and how (or whether) you can recover — and then makes you type confirm to send it. Read the consequences, then decide. The colour of each card tells you how carefully to read.

Reads are still the point. Writes are still the exception. The difference is that the guard rails are now informed consent, not a locked door.

SAFE — read or display-math only CAUTION — changes feel/behaviour, reversible DANGEROUS — destructive / state-changing CATASTROPHIC — brick / EEPROM / interlock class

01 Read commands 14 · all SAFE

One-shot snapshots. They ask the bike a question and print the answer — nothing is changed, toggled, or written. These are the whole point of a diagnostics session, and every one is safe to auto-run in the baseline.

version SAFE

Show firmware and board revision.

What it doesPrints the MBB firmware + board revision banner (READ_TIPS: 'Firmware + board revision.'). Rev-41 version reply also ends with a 'Reset Source:' line reporting the last reset cause; that is normal, not a reboot.

help SAFE

Show the console's own command menu.

What it doesPrints the console's built-in command menu (READ_TIPS: 'The console's own command menu.'). Verified live: logged in, 'help' shows the real menu; the menu differs by login level (003_help.txt pre-login / 019_help.txt post-login).

status SAFE

Show current bike status.

What it doesOverall bike status right now: mode, temps, SOC, faults (READ_TIPS).

stats SAFE

Show lifetime statistics.

What it doesLifetime statistics: odometer, top speed, all-time max temps (READ_TIPS).

runtime SAFE

Show total run and charge time.

What it doesTotal run time and total charge time (READ_TIPS).

bms SAFE

Show battery pack data.

What it doesBattery pack: cell voltages, balance, capacity, isolation, cycles (READ_TIPS).

sevcon SAFE

Show motor controller (Sevcon) data.

What it doesMotor controller (Sevcon) data (READ_TIPS). Bare 'sevcon' is a read; 'sevcon preop' is separately blocked as a write.

chargers SAFE

Show onboard charger status.

What it doesOnboard charger port status (READ_TIPS).

inputs SAFE

Show raw sensor inputs.

What it doesRaw sensor inputs: rail voltages, kill switch, kickstand, etc. (READ_TIPS).

outputs SAFE

Show output states.

What it doesOutput states: DC/DC, warning light, contactor enable, etc. (READ_TIPS). Read-only reporting of output state; does not toggle outputs.

dash SAFE

Show instrument-cluster data.

What it doesInstrument-cluster data: clock, odometer, CAN age (READ_TIPS).

obd SAFE

Show OBD summary (protocol, DTCs).

What it doesOBD summary: protocol, DTCs (READ_TIPS: 'Show all obd info'). Menu-verified at both login levels but its live OUTPUT has not been captured yet, so the full baseline runs it LAST; an empty reply is treated as possibly command-specific, not necessarily a sleeping console. It is a read only.

eeprom SAFE

Show EEPROM usage summary (bare form only).

What it doesBare 'eeprom' with no arguments is a READ on rev 41 - 'Show EEPROM usage' (a usage summary). Only the bare form is permitted; 'eeprom' WITH arguments is refused because it can read/modify raw EEPROM (see 'eeprom set' / 'format eeprom' entries).

errorlogdump SAFE

Dump the small error log (~1 KB, safe).

What it doesReads the error log (READ_TIPS: 'The small error log (~1 KB, safe).'). This is the only dump-class command safe to auto-run in the full baseline. Note: 'dumplogs' does NOT exist on rev 41 (bike replies 'invalid command'); errorlogdump is the real small-log read.

02 Heavy reads 2 · ⚠ contactor risk

Still read-only — they change no data — but they stream ~1 MB for minutes at 38400 baud and monopolize the MBB. While the console is tied up, the BMS can protectively open the drivetrain contactor (audible click, flashing dash). Park the bike first; these are never auto-run.

⚠ Park before running A long dump can starve the MBB's CAN servicing enough that the drivetrain contactor briefly opens. If the bike were moving, the drivetrain would drop out. Observed-live behaviour, not theoretical — run these stationary only.
eventlogdump CAUTION

Dump the full event log (~1 MB, minutes) - can briefly open the contactor.

What it doesReads the entire event log (~8600 entries / ~1 MB). At 38400 baud it streams for MINUTES and monopolizes the MBB long enough that it stops servicing the Sevcon/CAN bus. READ_TIPS: 'can briefly OPEN the drivetrain contactor. Park the bike first.' It is a read - it does not modify anything - and is never auto-run; the GUI gates it behind an explicit confirm dialog.

⚠ What could happenThe BMS protectively OPENS the drivetrain contactor while the console is monopolized (observed live: audible click + flashing dash). If the bike were moving, the drivetrain would drop out. It also ties up the console for minutes.
Reversible?Yes - no data is changed; the contactor re-closes on its own once the read finishes. It is a read-only side effect, not a persistent state change.
How to recoverWait for the dump to complete; the bike re-closes the contactor automatically and the dash returns to normal. Park the bike before running so a mid-ride contactor open is not a hazard.
dumpall CAUTION

Dump everything incl. logs (~1 MB, minutes) - same contactor caveat.

What it doesDumps everything including the event logs (READ_TIPS: 'Everything incl. logs (~1 MB, minutes) - same contactor caveat.'). Because it includes the full event log it carries the same heavy/monopolize-the-console behavior as eventlogdump. Read-only content, never auto-run, GUI-gated behind a confirm dialog.

⚠ What could happenSame as eventlogdump: while the console is monopolized for minutes the BMS can protectively OPEN the drivetrain contactor (audible click + flashing dash).
Reversible?Yes - it reads data only; the contactor re-closes itself once the dump finishes. No persistent change.
How to recoverLet the dump finish; the bike re-closes the contactor automatically. Park the bike first.

03 Writes 14 · whitelist, gated flow

The only settings OpenMBB will help you change. Each goes through the gated Writes tab — journaled, backed up, confirmed, sent, then read back and verified with a per-entry revert. Rows appear only for whitelisted names that are present in your bike's live dump. Change one thing at a time.

Safe — display math only (3)

set spfront <v> SAFE

Set front sprocket tooth count (speedo/odo math only).

What it doesWRITE_WHITELIST 'spfront' - 'Sprocket teeth, front'. Input to speedometer/odometer calculation ONLY; set to the physically installed front sprocket count (FX/FXS factory is 20). Validator: whole number 10-40. Risk text: 'SAFE - display math only. Wrong values skew speed/odo/Wh-per-km.' Written only via the gated Writes tab, which backs up, confirms, verifies and journals.

set sprear <v> SAFE

Set rear sprocket tooth count (speedo/odo math only).

What it doesWRITE_WHITELIST 'sprear' - 'Sprocket teeth, rear'. Input to speedo/odo calculation ONLY; set to the installed rear sprocket count (FX/FXS factory is 90). Validator: whole number 30-150. Risk text: 'SAFE - display math only.' Gated Writes-tab path only.

set rwhcirc <v> SAFE

Set rear wheel circumference in mm (speedo math only).

What it doesWRITE_WHITELIST 'rwhcirc' - 'Rear wheel circumference (mm)'. Input to speedo calculation; trim so speedo matches GPS (typically ~1900-2000 mm). Validator: whole number 1500-2400. Risk text: 'SAFE - display math only.' Gated Writes-tab path only.

Caution — changes feel or gauge behaviour (11)

set maxcustspmph <v> CAUTION

Set Custom-mode max speed in mph.

What it doesWRITE_WHITELIST 'maxcustspmph' - 'Custom mode: max speed (mph)'. Top speed in Custom ride mode (real rev-41 name maxcustspmph). Physical ceiling ~85 mph; console accepts up to 102. Validator: whole number 20-102. Risk text labels it SAFE (factory-supported parameter space). Gated Writes-tab path only.

⚠ What could happenSets the Custom ride-mode speed cap. Values above the bike's ~85 mph physical ceiling are accepted by the console but not physically achievable; it stays within the factory-supported parameter space.
Reversible?Yes - it is a whitelisted, journaled setting; re-run the write with the prior value (captured in the writes journal / 'set' dump) to restore it.
How to recoverRe-write the previous value via the Writes tab; the write flow journals old->new so the prior value is recorded.
set maxcusttq_allowed <v> CAUTION

Set Custom-mode max torque (% of allowed).

What it doesWRITE_WHITELIST 'maxcusttq_allowed' - 'Custom mode: max torque (% of allowed)'. Torque cap in Custom mode, % of what the Sevcon allows (real name maxcusttq_allowed). Validator: whole number 10-100. Risk text labels it SAFE (factory-supported parameter space). Gated Writes-tab path only.

⚠ What could happenChanges how much torque Custom mode delivers as a percentage of the Sevcon-allowed maximum; stays within factory-supported bounds. Higher values increase acceleration/aggressiveness within limits.
Reversible?Yes - whitelisted and journaled; restore by re-writing the prior value.
How to recoverRe-write the previous value via the Writes tab (old value is journaled).
set maxcustregcotq_allow <v> CAUTION

Set Custom-mode coast (off-throttle) regen (% of allowed).

What it doesWRITE_WHITELIST 'maxcustregcotq_allow' - 'Custom mode: coast regen (% of allowed)'. Off-throttle coast regen in Custom mode, % of allowed (real name maxcustregcotq_allow). Validator _v_coast_regen: whole number 0-100 but EXACTLY 0 is refused (0% coasting regen can cause fishtailing in low traction). Risk text: 'SAFE, but exactly 0 is refused (fishtail risk in low traction).' Gated Writes-tab path only.

⚠ What could happenChanges off-throttle regen braking feel. Very low values give free coasting; exactly 0 is refused because zero coast regen can cause fishtailing in low traction.
Reversible?Yes - whitelisted and journaled; restore by re-writing the prior value.
How to recoverRe-write the previous value via the Writes tab (old value is journaled).
set maxcustregbrtq_allow <v> CAUTION

Set Custom-mode brake regen (% of allowed).

What it doesWRITE_WHITELIST 'maxcustregbrtq_allow' - 'Custom mode: brake regen (% of allowed)'. Regen applied when the brake switch triggers, in Custom mode (real name maxcustregbrtq_allow). Validator: whole number 0-100. Risk text labels it SAFE (factory-supported parameter space). Gated Writes-tab path only.

⚠ What could happenChanges how much regen is applied when the brake switch triggers in Custom mode; affects brake feel. Stays within factory-supported bounds.
Reversible?Yes - whitelisted and journaled; restore by re-writing the prior value.
How to recoverRe-write the previous value via the Writes tab (old value is journaled).
set brakeregen <v> CAUTION

Set whether the brake switch applies max brake regen (Yes/No).

What it doesWRITE_WHITELIST 'brakeregen' - 'Apply regen on brake switch'. Whether the brake light switch applies max brake regen. Validator _v_yes_no. Risk text: 'CAUTION - modest changes only; affects brake feel.' Note: whitelisted but not observed on the verified rev 41 (not in REV41_FXS_SETTINGS); the transport refuses a write to a name absent from the live 'set' dump. Gated Writes-tab path only.

⚠ What could happenChanges braking behavior/feel by tying (or untying) max brake regen to the brake switch. Modest changes only are advised.
Reversible?Yes - whitelisted and journaled; restore by re-writing the prior value. On rev 41 it may not be present at all, in which case the write is refused before it reaches the wire.

Set brake-switch filter delay in ms.

What it doesWRITE_WHITELIST 'brakefilter' - 'Brake switch filter (ms)'. Delay after the brake switch closes before the light + regen trigger. Validator: whole number 0-1000. Risk text: 'CAUTION - keep near default (100 ms).' May be absent on rev 41 (not in REV41_FXS_SETTINGS); transport refuses writes to names absent from the live dump. Gated Writes-tab path only.

⚠ What could happenChanges the delay before the brake light and brake regen engage after the switch closes. Far-from-default values change brake responsiveness.
Reversible?Yes - whitelisted and journaled; restore by re-writing the prior value (default ~100 ms).
How to recoverRe-write the previous value via the Writes tab (old value is journaled).
set noregenstopped <v> CAUTION

Set the low-speed regen guard (leave Yes).

What it doesWRITE_WHITELIST 'noregenstopped' - 'Prevent regen at low speed'. Blocks regen below ~13 mph. Validator _v_yes_no. Risk text: 'CAUTION - safe-direction only: leave enabled (Yes). Disabling removes a low-speed stability guard.' Has a warn_fn that fires when set to No/off/0. May be absent on rev 41. Gated Writes-tab path only.

⚠ What could happenSetting this to 'No' removes the low-speed regen stability guard, allowing regen below ~13 mph - a stability risk at low speed. The write flow warns explicitly on a disabling value.
Reversible?Yes - whitelisted and journaled; restore by re-writing 'Yes'. The safe direction is to leave it enabled.
How to recoverRe-write 'Yes' via the Writes tab (old value is journaled).
set reserve_sw <v> CAUTION

Toggle the SOC reserve partition (Yes/No).

What it doesWRITE_WHITELIST 'reserve_sw' - 'Use SOC reserve partition'. Treats part of the battery as a 'fuel reserve' partition. Validator _v_yes_no. Risk text: 'CAUTION - changes what the gauge withholds, not real capacity. On an aged pack, don't reduce your reserve margin.' Gated Writes-tab path only.

⚠ What could happenEnables/disables the gauge's reserve partition. This changes what the gauge WITHHOLDS, not real capacity (adds zero real Ah). On an aged pack, dropping the reserve reduces your safety margin before empty.
Reversible?Yes - whitelisted and journaled; restore by re-writing the prior value.
How to recoverRe-write the previous value via the Writes tab (old value is journaled).
set reserve_pct <v> CAUTION

Set reserve partition size (%).

What it doesWRITE_WHITELIST 'reserve_pct' - 'Reserve partition size (%)'. How much SoC the reserve partition withholds (default 33%). Validator: whole number 0-50. Risk text: 'CAUTION - gauge behavior only, adds zero real Ah.' Gated Writes-tab path only.

⚠ What could happenChanges how much SoC the gauge withholds as reserve. Gauge behavior only - adds zero real Ah. Lowering it reduces displayed margin before empty.
Reversible?Yes - whitelisted and journaled; restore by re-writing the prior value (default 33).
How to recoverRe-write the previous value via the Writes tab (old value is journaled).
set fuelgaugepes <v> CAUTION

Set fuel-gauge pessimism (%).

What it doesWRITE_WHITELIST 'fuelgaugepes' - 'Fuel gauge pessimism (%)'. SoC display buffer (default 5%); shifts only the DISPLAYED percentage, not actual pack charge. Validator: whole number 0-20. Risk text: 'CAUTION - reducing it removes low-SOC margin on an aged pack.' warn_fn fires for values < 5. Gated Writes-tab path only.

⚠ What could happenShifts the displayed SoC buffer. Display only - does not change actual charge. Lowering it (below the default 5%) removes low-SOC display safety margin on an aged pack; the write flow warns on values under 5.
Reversible?Yes - whitelisted and journaled; restore by re-writing the prior value (default 5).
How to recoverRe-write the previous value via the Writes tab (old value is journaled).
set chgstby <v> CAUTION

Set charge standby time before rebalance (minutes).

What it doesWRITE_WHITELIST 'chgstby' - 'Charge standby time (min)'. How long the BMS sleeps after reaching 100% before waking to rebalance cells (default 1440 = 24 h). Validator: whole number 60-10080. Risk text: 'CAUTION - affects balancing cadence; the default is usually right.' Gated Writes-tab path only.

⚠ What could happenChanges how often the BMS wakes to rebalance cells after a full charge. Affects balancing cadence; the default (1440 min = 24 h) is usually correct, and unusual values change how frequently balancing occurs.
Reversible?Yes - whitelisted and journaled; restore by re-writing the prior value (default 1440).
How to recoverRe-write the previous value via the Writes tab (old value is journaled).

04 Dangerous / destructive 55 · type “confirm” to send

These change state, erase data, defeat safety interlocks, or touch firmware. OpenMBB will send them — but only after you have read the consequences below and typed confirm. Pink is destructive/state-changing; red is brick / EEPROM / interlock class and may be unrecoverable. Capture your logs and a full set dump before anything here.

⚠ No undo for most of these Cleared logs, wiped EEPROM, reset stats, flashed/bootloader firmware, and defeated interlocks (ABS, BMS, isolation) are largely irreversible from the console. Where recovery exists at all it often needs vendor/dealer tooling. Read every card fully.
dtc_clear DANGEROUS

Clear stored diagnostic trouble codes.

What it doesClears stored DTCs (BLOCKED_COMMANDS comment: 'clears stored DTCs'). On the hard blocklist - the transport refuses to send it from any path, including the raw box.

⚠ What could happenErases the stored fault history the bike (and a technician) would use to diagnose a problem. The clearing itself is a deliberate state change; a real underlying fault will simply re-log if still present, but past evidence is gone.
Reversible?No - cleared DTCs cannot be un-cleared; the historical fault records are permanently gone.
How to recoverNot recoverable without a prior log capture. Run errorlogdump/eventlogdump BEFORE any clear to preserve the record; there is no console way to restore cleared codes.
force_all_storage_mode DANGEROUS

Force all battery modules into storage mode.

What it doesForces the battery modules into storage mode (BLOCKED_COMMANDS comment: 'forces battery modules into storage mode'). On the hard blocklist - never sent.

⚠ What could happenCommands the pack toward its storage state of charge / storage behavior, changing pack management state deliberately. Exact firmware-side effects and whether it self-discharges cells are not fully documented in the repo.
Reversible?Unknown / treat as potentially irreversible - the repo does not document a clean inverse, and any self-discharge toward a storage SOC would not be undone by simply exiting the mode.
How to recoverNot documented. Best effort would be a normal charge cycle to bring the pack back up, but any state change or discharge caused by storage mode may not be cleanly reversible; treat as unrecoverable without vendor tooling.
blcmds CATASTROPHIC

Bootloader command block.

What it doesBootloader command block (BLOCKED_COMMANDS comment: 'bootloader command block'). Exposes bootloader-level operations. On the hard blocklist - never sent.

⚠ What could happenGives access to bootloader commands that can alter or erase firmware / low-level state. Effects are undocumented in the repo and potentially brick-class.
Reversible?No / unknown - bootloader-level operations can leave firmware in an unbootable state with no console-level undo.
How to recoverNot recoverable without a firmware reflash via vendor/dealer tooling; potentially requires MBB replacement if the bootloader path corrupts firmware.
burn CATASTROPHIC

Bluetooth BMS firmware updater (firmware flashing).

What it doesBluetooth BMS firmware updater = firmware flashing (BLOCKED_COMMANDS comment: 'bluetooth BMS firmware updater'). On the hard blocklist - never sent.

⚠ What could happenInitiates a firmware flash of the Bluetooth BMS. An interrupted or wrong flash can brick the target module.
Reversible?No - flashing overwrites firmware; a failed/partial flash is not undoable from the console.
How to recoverNot recoverable without a successful re-flash via vendor tooling; a bricked module may need replacement.
format CATASTROPHIC

Wipe EEPROM (covers 'format eeprom').

What it doesFirst token 'format' is hard-blocked; it covers 'format eeprom' which wipes the EEPROM (safety.py header comment). Never sent.

⚠ What could happenErases the EEPROM contents - configuration, calibration and identity data stored there are wiped.
Reversible?No - a format destroys stored data; there is no console undo.
How to recoverNot recoverable without a full known-good EEPROM image restored via vendor tooling; loss of calibration/identity may require dealer reprogramming.
erase CATASTROPHIC

Wipe EEPROM (covers 'erase eeprom').

What it doesFirst token 'erase' is hard-blocked; it covers 'erase eeprom' which wipes the EEPROM (safety.py header comment). Never sent.

⚠ What could happenErases EEPROM contents - stored configuration/calibration/identity is destroyed.
Reversible?No - an erase destroys stored data with no console undo.
How to recoverNot recoverable without restoring a known-good EEPROM image via vendor tooling; may require dealer reprogramming.
eeprom set CATASTROPHIC

Modify raw EEPROM (any 'eeprom' with arguments).

What it does'eeprom' WITH arguments (e.g. 'eeprom set') can read or MODIFY raw EEPROM and is refused; only bare 'eeprom' (the read-only usage summary) is allowed (_line_blocked).

⚠ What could happenWrites raw bytes into EEPROM, corrupting configuration/calibration/identity if wrong. Direct raw writes bypass all validation.
Reversible?No - a raw EEPROM write overwrites the prior bytes; there is no console undo and no journal of the old value.
How to recoverNot recoverable without a known-good EEPROM image restored via vendor tooling.

⚠ What could happenReverts all configurable settings to firmware defaults, discarding any custom configuration (sprocket/speedo calibration, ride-mode customization, reserve, etc.).
Reversible?Partially - you can re-enter each setting IF you recorded the prior values first; the reset itself provides no undo.
How to recoverRe-apply each setting by hand from a prior full 'set' dump. Without a saved dump the old values are lost.

reset CAUTION

⚠ What could happenThe MBB reboots mid-session: login level and console state are lost (transport treats a boot banner as a ConsoleRebootError). If sent while riding, a controller reset drops normal operation.
Reversible?Partially - a reset is a reboot, not a data change, so the bike comes back up; but the current session and any in-progress operation are lost.
